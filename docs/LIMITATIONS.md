# Технічні обмеження

1. **Немає універсального протоколу.** Розширені функції можливі лише для брендів із реалізованим драйвером; решта отримує Universal-рівень.
2. **Один застосунок на канал.** Офіційний застосунок виробника може тримати RFCOMM/GATT-канал — його треба закрити.
3. **Заряд без драйвера** доступний лише через Fast Pair Message Stream або BLE Battery Service. Прихований API Android для заряду Bluetooth (`getBatteryLevel`) свідомо не використовується (вимога: без прихованих API).
4. **Fast Pair-канал** може бути зайнятий Google Play Services на деяких телефонах — тоді джерело недоступне.
5. **LE-адреса.** Деякі TWS-навушники мають GATT на окремій LE-адресі («NAME-LE»); застосунок шукає таких двійників у результатах BLE-сканування — для цього треба хоча б раз запустити сканування.
6. **Глобальний еквалайзер** Android обмежує (ефекти на сесію 0 застаріли й працюють не на всіх пристроях). У v0.1 профілі лише зберігаються; застосування — v0.2.
7. **Фонова робота.** Таймер сну й відновлення з’єднання працюють, поки процес застосунку живий; foreground-сервіс — у v0.3.
8. **Apple.** Керування AirPods (AAP через L2CAP) не має публічного API Android; доступний лише заряд з оголошень, з кроком 10%.
9. **Android 10–11**: для BLE-сканування потрібен дозвіл на місцезнаходження і ввімкнена геолокація (обмеження ОС; дані місцезнаходження не використовуються).
10. **Перевірка**: жодна модель ще не має статусу Verified — фізичне тестування лише починається.
11. **Локалізація**: примітки драйверів у каталозі та Lab поки англійською.
